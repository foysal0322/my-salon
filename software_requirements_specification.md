# Software Requirements Specification (SRS)
**Project Name:** AmarSaloon (আমার সেলুন) — Smart Salon & Beauty Parlor Booking & Queue Management Platform  
**Standard Compliance:** IEEE Std 830 / ISO/IEC/IEEE 29148  
**Version:** 1.0  
**Date:** October 16, 2026  
**Target Region:** Bangladesh (Primary Locale: `bn-BD`, Secondary: `en-US`)

---

## 1. Introduction

### 1.1 Purpose
This Software Requirements Specification (SRS) provides a complete technical description of the **AmarSaloon** Progressive Web Application (PWA). It defines functional behavior, system states, API interfaces, database constraints, and non-functional performance metrics required by software engineers, QA testers, and DevOps architects to build and deploy the system.

### 1.2 Scope
AmarSaloon is a multi-tenant, real-time salon discovery, virtual queue management, appointment scheduling, and digital bookkeeping web application designed to operate like a native mobile app. Key subsystems include:
1. **Customer PWA:** Geolocation-based discovery, QR code profile resolution, guest/authenticated live queue joining, appointment booking, and live token tracking.
2. **Salon Owner Portal:** Multi-branch salon management, service catalog builder, real-time chair & walk-in queue console, A4 printable QR poster generator, and daily income/expense ledger (*Hishab Khata*).
3. **Super Admin Portal (`/admin`):** Role management, salon moderation, and MFS/Bank subscription verification.

### 1.3 Definitions, Acronyms, and Abbreviations
* **PWA:** Progressive Web Application (installable web app via Service Workers and Web App Manifest).
* **OTP:** One-Time Password sent via SMS gateway.
* **MFS:** Mobile Financial Services in Bangladesh (bKash, Nagad, Rocket).
* **RBAC:** Role-Based Access Control.
* **TrxID:** Transaction ID generated by an MFS provider.
* **Walk-in Queue ($Q_{\text{manual}}$):** Customers physically waiting inside a salon who did not book via the app.
* **App Queue ($Q_{\text{online}}$):** Customers who joined the waiting line digitally via the app.

## 2. Overall Description

### 2.1 Product Perspective
The system follows a client-server architecture with real-time bi-directional WebSocket communication:
* **Client Tier:** Next.js (React) PWA rendered inside a mobile-constrained viewport (`max-width: 480px`) for Customers and Salon Owners, and a responsive desktop layout for `/admin`.
* **Application Tier:** Node.js REST/GraphQL API + WebSocket Server (Socket.io / Supabase Realtime) for live chair and queue state synchronization.
* **Data Tier:** PostgreSQL with PostGIS for spatial queries and Redis for OTP TTL caching and pub/sub socket events.
* **External Integrations:** Local BD SMS Gateway (OTP & alerts), Web Push (VAPID), Google Maps / OpenStreetMap API, and MFS Payment Gateways.

### 2.2 User Classes and Characteristics
| User Class | Access Route | Authentication | Primary Capabilities |
| :--- | :--- | :--- | :--- |
| **Guest Customer** | `/` or `/s/{slug}` | Unauthenticated (Phone OTP required only at checkout) | Search/filter salons, scan QR codes, view live chair/queue status, book queue/appointment. |
| **Registered Customer** | `/login` (Customer Tab) | Phone (`+8801XXXXXXXXX`) + 6-digit OTP | All Guest features + save to "My Saloons", receive Web Push notifications, view active/past bookings. |
| **Salon Owner** | `/login` (Owner Tab) | Phone (`+8801XXXXXXXXX`) + 6-digit OTP | Strictly isolated dashboard. Manage multiple salons, toggle chairs, manage queue, download A4 QR PDF, record daily sales/expenses, purchase subscriptions. |
| **Super Admin** | `/admin` | Email/Phone + Password + 2FA | Manage user roles, approve/edit/block/delete salons, verify MFS/Bank subscriptions. |

### 2.3 Operating Environment
* **Mobile Browsers:** Chrome for Android (v90+), Safari on iOS (v15.4+ with Web Push support), Samsung Internet, UC Browser.
* **Desktop Browsers:** Chrome, Edge, Firefox, Safari (for `/admin` and A4 PDF printing).
* **Network Conditions:** Optimized for 3G/4G mobile networks in Bangladesh with intermittent connectivity handling.

### 2.4 Assumptions and Dependencies
* Salon owners have access to an Android/iOS smartphone with an active internet connection to update chair/queue states.
* Physical walk-in customers will be accounted for by the salon owner tapping the `+` or `-` queue counter on their dashboard.

## 3. System Features & Functional Requirements

### 3.1 Authentication & Role Isolation (`FR-AUTH`)
* **FR-AUTH-01 (BD Phone Validation):** The system shall validate phone numbers against the Bangladesh standard regex: `^(?:\+88|88)?(01[3-9]\d{8})$`.
* **FR-AUTH-02 (OTP Generation & Rate Limiting):** Upon login/registration request, the system shall generate a 6-digit numeric OTP valid for $180\text{ seconds}$. Maximum 3 OTP requests per phone number per $600\text{ seconds}$.
* **FR-AUTH-03 (Separate Login Flows):** The `/login` screen shall present two distinct tabs: **"গ্রাহক (Customer)"** and **"সেলুন মালিক (Salon Owner)"**.
* **FR-AUTH-04 (Owner Route Isolation):** When authenticated with role `OWNER`, the user shall be strictly redirected to `/owner/dashboard` and prevented from accessing customer discovery routes unless they explicitly switch context or log out.
* **FR-AUTH-05 (Admin Dedicated Route):** The `/admin` route shall present an isolated login screen. Attempting to access `/admin/*` with `CUSTOMER` or `OWNER` JWT tokens shall return HTTP `403 Forbidden`.

### 3.2 PWA & Localization Engine (`FR-PWA`)
* **FR-PWA-01 (Persistent Top Install Banner):** If the app is running in a standard browser tab (`window.matchMedia('(display-mode: standalone)').matches === false`), a sticky top bar shall render across all public pages prompting the user to install the PWA.
* **FR-PWA-02 (Install Trigger):** Clicking the top banner's "ইনস্টল করুন (Install)" button shall invoke the captured `beforeinstallprompt` event (or display iOS "Add to Home Screen" instructions on Safari). Once installed, the banner shall permanently hide.
* **FR-PWA-03 (Bilingual Support):** The UI shall default to **Bangla (`bn`)** and provide a 1-tap toggle to **English (`en`)**. Language state shall persist in `localStorage` and user profile settings.

### 3.3 Customer Discovery, Search & QR Resolution (`FR-CUST`)
* **FR-CUST-01 (Geospatial Discovery):** On home load, the system shall request GPS coordinates $(\phi, \lambda)$ and query active salons within a configurable radius (default $5\text{ km}$), sorted by Haversine distance:
  $$d = 2r \arcsin\left(\sqrt{\sin^2\left(\frac{\Delta \phi}{2}\right) + \cos(\phi_1)\cos(\phi_2)\sin^2\left(\frac{\Delta \lambda}{2}\right)}\right)$$
* **FR-CUST-02 (Multi-Faceted Filtering):** Users shall filter salons by:
  * **Category:** `GENTS` (জেন্টস), `LADIES` (লেডিস বিউটি পার্লার), `UNISEX`.
  * **Facility:** `AC` (এসি) vs. `NON_AC` (নন-এসি).
  * **Search Query:** Partial text match on Salon Name (Bangla/English), Address, or Service Name.
* **FR-CUST-03 (QR Code Deep Linking):** Scanning a salon's QR code (`https://{domain}/s/{salon_slug}?ref=qr`) shall route the user directly to that salon's profile page and prompt a floating action button: **"Add to My Saloons (প্রিয় সেলুনে যুক্ত করুন)"**.
* **FR-CUST-04 (Favorite Saloons Gate):** If an unauthenticated Guest taps "Add to My Saloons", the system shall open a slide-up OTP login modal, authenticate the user, automatically append the salon to `favorite_saloons`, and subscribe the user's device token to that salon's notification topic.

### 3.4 Live Queue & Appointment Booking (`FR-BOOK`)
* **FR-BOOK-01 (Service Multi-Select):** Users shall select one or more active services from the salon profile. The UI shall dynamically compute:
  $$\text{Total Cost} = \sum_{i=1}^{n} P_i, \quad \text{Total Duration} = \sum_{i=1}^{n} D_i$$
* **FR-BOOK-02 (Guest Checkout Verification):** Guests booking without an account must enter their Name and Phone Number and verify via a 1-time OTP before the booking token is committed. Each phone number is restricted to maximum **1 active live queue booking** globally at any given time.
* **FR-BOOK-03 (Token Generation):** Upon joining the live queue, the system shall atomically increment the salon's daily token sequence (resetting at `00:00` local time, UTC+6) and issue a Token Number (e.g., `#014`).
* **FR-BOOK-04 (Live Waiting Number Tracker):** The customer's active booking screen shall subscribe via WebSockets to display:
  1. Total Chairs & Currently Busy Chairs.
  2. Current Token Being Served.
  3. Customer's Token Number & Position in Queue ($Q_{\text{ahead}}$).
  4. Estimated Wait Time ($T_{\text{wait}}$):
     $$T_{\text{wait}} = \left\lceil \frac{(Q_{\text{online\_ahead}} + Q_{\text{manual}}) \times \bar{D}_{\text{service}}}{\max(C_{\text{total}}, 1)} \right\rceil$$

### 3.5 Salon Owner Multi-Branch & Floor Console (`FR-OWN`)
* **FR-OWN-01 (Multi-Salon Management):** An owner account shall support creating and managing $N \ge 1$ salons. A persistent header selector shall switch the active `saloon_id` context across all owner tabs.
* **FR-OWN-02 (Salon Registration & Profile):** Owners shall input/edit: Salon Name, Address, Google Map Pin (`lat`, `lng`), Contact Number, Category (`GENTS`/`LADIES`/`UNISEX`), AC Status (`boolean`), and Total Chairs/Desks ($C_{\text{total}} \in [1, 50]$).
* **FR-OWN-03 (Service Catalog Management):** Owners shall create, update, or toggle services (e.g., Hair Cutting, Beard Shave, Facial, Pedicure, Manicure, Spa, Face Pack) with attributes: Service Name, Rate (BDT), Duration (mins), and Details.
* **FR-OWN-04 (Real-Time Chair Controller):** The owner dashboard shall render interactive cards for each chair $c \in \{1 \dots C_{\text{total}}\}$. Tapping a chair toggles its state between `AVAILABLE` (Green) and `BOOKED` (Red) and broadcasts the state change to all connected clients in $< 500\text{ ms}$.
* **FR-OWN-05 (Hybrid Queue Counter):** Owners shall adjust the physical walk-in queue count ($Q_{\text{manual}}$) using `+` and `-` buttons and advance online tokens (`WAITING` $\rightarrow$ `IN_SERVICE` $\rightarrow$ `COMPLETED` / `NO_SHOW`).

### 3.6 Printable A4 QR Poster Generator (`FR-QR`)
* **FR-QR-01 (QR Generation):** Each salon shall have a permanent high-error-correction (Level H) QR code encoding its canonical URL.
* **FR-QR-02 (A4 Poster Layout & Export):** The system shall render a branded, print-ready A4 template ($210\text{ mm} \times 297\text{ mm}$ at $300\text{ DPI}$ equivalent vector PDF) displaying:
  * Salon Name, Address, Phone Number, and AC/Category badges.
  * Central QR Code.
  * Step-by-step instructions in Bangla & English on how to scan, add to "My Saloons", and book online.
* **FR-QR-03 (Share & Download):** Owners can download the `.pdf` file directly for printing/laminating or share a social media image card via the Web Share API.

### 3.7 Salon Financial Ledger / *Hishab Khata* (`FR-LEDG`)
* **FR-LEDG-01 (Automated & Manual Entries):**
  * Marking an app booking as `COMPLETED` shall prompt a 1-tap action to log `total_amount` as an `INCOME` record.
  * Owners can manually add `INCOME` (walk-in services) and `EXPENSE` (rent, utility, supplies, staff payout) entries with date, category, amount, and notes.
* **FR-LEDG-02 (Aggregated Reporting):** The system shall compute Daily, Monthly, and Yearly aggregations:
  $$\text{Net Profit} = \sum \text{Income}_{\text{period}} - \sum \text{Expense}_{\text{period}}$$
* **FR-LEDG-03 (Data Export):** Owners shall export ledger records for any selected date range (Daily, Monthly, Yearly) in `.CSV`, `.XLSX`, and printable `.PDF` formats.

### 3.8 Subscription & Monetization Engine (`FR-SUB`)
* **FR-SUB-01 (30-Day Free Trial):** Upon creation of a new salon, the system shall set `trial_ends_at = created_at + 30 days` and `subscription_status = TRIAL`.
* **FR-SUB-02 (Package Selection & Payment Submission):** Owners can select a **Monthly** or **Yearly** package and pay via:
  * **MFS (bKash / Nagad / Rocket):** Automated gateway webhook or manual submission of Sender Number + `TrxID`.
  * **Bank Transfer:** Upload of bank deposit slip image (`.jpg`/`.png`/`.pdf`, max $5\text{ MB}$) + Reference Number.
* **FR-SUB-03 (Expiration Lockout):** If `current_time > max(trial_ends_at, subscription_ends_at)`, the salon's public visibility shall be suspended, and the owner's Live Queue Console shall display a renewal paywall while preserving read/export access to the Sales Ledger.

### 3.9 Super Admin Portal (`FR-ADM`)
* **FR-ADM-01 (User & Role Control):** Admin at `/admin` can search users, modify roles (`CUSTOMER`, `OWNER`, `ADMIN`), or suspend accounts.
* **FR-ADM-02 (Salon Moderation):** Admin can create a salon on behalf of an owner, edit any salon's metadata, soft-delete, or toggle `status = BLOCKED` (instantly terminating active public listings).
* **FR-ADM-03 (Subscription Approval):** Admin can inspect pending MFS `TrxID`s and Bank Transfer slips and click `Approve` (which extends `subscription_ends_at` by $30$ or $365$ days) or `Reject` with a reason note.

## 4. External Interface Requirements

### 4.1 User Interfaces (UI Architecture)
* **Customer & Owner Viewport:** Mobile-first container (`max-width: 480px`), fixed bottom navigation bar (`height: 64px`), sticky top status/PWA bar, zero horizontal scrolling, touch targets $\ge 48 \times 48\text{ px}$.
* **Admin Viewport (`/admin`):** Responsive 12-column desktop dashboard layout with sidebar navigation, data tables with pagination, and modal drawers.

### 4.2 Core REST API Endpoints
| Method | Endpoint | Role | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/auth/otp/send` | Public | Sends 6-digit OTP to BD phone number. |
| `POST` | `/api/v1/auth/otp/verify` | Public | Verifies OTP and returns JWT + User Role. |
| `GET` | `/api/v1/saloons` | Public | Lists active salons with geo, gender, AC, and search filters. |
| `GET` | `/api/v1/saloons/:slug` | Public | Fetches full salon details, services, and live chair/queue status. |
| `POST` | `/api/v1/bookings` | Guest/Cust | Creates a live queue token or scheduled booking. |
| `PATCH` | `/api/v1/owner/saloons/:id/state` | Owner | Updates chair availability and manual walk-in queue count. |
| `GET` | `/api/v1/owner/saloons/:id/qr-pdf` | Owner | Generates and streams the A4 printable QR PDF. |
| `GET/POST`| `/api/v1/owner/saloons/:id/ledger` | Owner | Fetches or logs daily sales/expenses; supports `?export=csv\|pdf`. |
| `POST` | `/api/v1/owner/subscriptions` | Owner | Submits MFS/Bank payment for Monthly/Yearly plan. |
| `PATCH` | `/api/v1/admin/saloons/:id/status` | Admin | Approves, blocks, or deletes a salon. |

### 4.3 Real-Time WebSocket Events
* **Channel `salon:{saloon_id}:live`:**
  * Server $\rightarrow$ Client `STATE_UPDATED`: `{ total_chairs, busy_chairs, current_token, total_queue, est_wait_mins }`
* **Channel `user:{user_id}:notifications`:**
  * Server $\rightarrow$ Client `BOOKING_ALERT`: `{ type: 'NEXT_IN_LINE' | 'TURN_READY', token_number, message_bn, message_en }`

## 5. Non-Functional Requirements (NFRs)

### 5.1 Performance & Latency
* **NFR-PERF-01:** Real-time chair toggle and queue counter updates shall propagate from the Owner Console to viewing Customers within $\le 500\text{ ms}$ (P95) over WebSockets.
* **NFR-PERF-02:** First Contentful Paint (FCP) on 4G mobile devices shall be $\le 1.5\text{ seconds}$ utilizing PWA Service Worker caching.

### 5.2 Security & Access Control
* **NFR-SEC-01:** All API routes shall enforce JWT signature verification and Role-Based Access Control (RBAC). Owners can only mutate resources where `saloon.owner_id === jwt.user_id`.
* **NFR-SEC-02:** The `/admin` portal shall enforce strict IP rate-limiting (max 5 failed login attempts per 15 minutes) and CSRF protection.

### 5.3 Reliability & Offline Resilience
* **NFR-REL-01:** If a Salon Owner loses internet connectivity while entering daily sales/expenses, the PWA shall queue the payload in `IndexedDB` and automatically sync via Background Sync once connectivity is restored.
